# 范文库

二十八篇，覆盖法定公文、事务性材料、基层党建三大类。**这些都不是真件。**

每篇顶部有一个 `>` 引用块，写明三件事：哪些内容可核实（政策文件名、文号、制度依据）、哪些走了占位符、哪些是虚构的。**发布前必须通读那一段。** 引用块以 `>` 开头，`check_params.py` 会自动跳过，不影响字数与参数统计。

## 一、法定公文（8 篇）

结构由制度锁定，不用统计参数，但版式和承启句必须对。

| 文种 | 篇目 | 看什么 |
|---|---|---|
| 通知 | 关于开展2026年度安全生产大检查的通知 | 承启句“现将……通知如下：”；目标—重点—要求三段；责任主体写到具体部门 |
| 请示 | 关于申请追加农村饮水安全巩固提升工程资金的请示 | 一文一事；“为什么、要多少、怎么用、不给会怎样”；结尾“妥否，请批示” |
| 批复 | 关于同意举办2026年XX市文化旅游节的批复 | **表态在最前**；承启句“收悉。现批复如下：”；请示没提的不主动加 |
| 复函 | 关于协助做好XX流域水质联合监测工作的复函 | 平行文不用命令语气，用“商请”“建议”；“专此函复”收束 |
| 会议纪要 | 县人民政府防汛抗旱专题会议纪要 | 纪要是“定了什么”不是“谁说了什么”；要素栏要齐；不用“某领导指出” |
| 报告 | 2026世界机器人大会举办情况的报告 | 上行报告的行文口气；结尾“特此报告” |
| 报告 | 落实免费学前教育政策情况的报告 | 同一文种的另一种形态（政策落实情况型） |

**读这八篇的注意事项**：法定公文没有统计参数，拿它们跑 `check_params.py --match` 会得到一个毫无意义的猜测（多半猜成调研报告或工作方案）。那个结果直接忽略——它只说明“参数体系不适用于法定公文”，不说明你写错了。

写法定公文时真正要对照的是 `参考/法定公文样例/` 里那七篇政府公开真件，看发文字号、主送机关、成文日期、公开标识怎么摆。本目录的范文只示范**行文逻辑**，不示范版式。

**工作总结这篇单独说明。** 它是全库唯一带“存在的问题”一节的范文，这不是疏漏——工作总结本来就要写问题，经验材料才不写。两篇对着读，能看清这条界线在哪：

```
工作总结  →「主要工作及成效」+「存在的问题」+「下半年打算」，问题要具体到哪件事没办好
经验材料  →  不出现本单位未解决的不足。可写已经克服的困难，用于增强可信度
```

## 四、两条使用须知

**一、范文借结构，不借内容。** 场面、人物、数据全是编的。你要的是一段真实调研、一个真名真姓的干部、一句原话——这些只能从你自己手上拿。

**二、别把范文当合格线。** 这些篇目是按参数写出来的，所以它们“很标准”。但真公文里写得好的那些，逐项跑自检反而常常不达标（句长从 26 到 56、顿号从 6‰ 到 42‰ 都有）。范文适合看**结构和节奏**，不适合当审美标杆。

## 五、怎么找到你要的那一篇

用文种名搜索即可，文件名前缀就是文种：

```bash
ls 示例 | grep 通知      # 法定公文按文种找
ls 示例 | grep 调研      # 事务性材料按文种找
```

同一文种有两篇以上的，选跟你手上任务**形态最接近**的那篇——事件型对情况型、事前部署对限期攻坚、城对乡、一老对一小。形态选错，参数再准也不像。
